**Security & reliability release — fixes all 14 issues from the comprehensive repository audit. No new features, just hardening.**

## 🔒 Security

### API key transport — header instead of URL query
The Gemini API key is now sent via the `x-goog-api-key` HTTP header instead of as a URL query parameter. URL query strings are logged by HTTP proxies, can appear in OS network diagnostics, and (per Google's own guidance) should not be used for credentials. *(src-tauri/src/commands/gemini.rs)*

### API key storage — opt-in persistence
The Gemini API key is **no longer persisted to localStorage by default**. localStorage is readable by any JavaScript on the same origin — including XSS payloads — so a leaked key was a single `localStorage.getItem` away. The key now lives in memory only and is cleared on app close. Users who explicitly want persistence can opt in via a new **"Remember API key on this device"** checkbox in the API Keys panel. A one-time migration wipes any pre-existing key from older versions. *(src/stores/settings-store.ts, src/components/ApiKeysView.tsx)*

### Content Security Policy — strict CSP enabled
Tauri's CSP was previously `null` (disabled). A strict CSP is now enforced: `script-src 'self'` blocks injected scripts, `connect-src` whitelists only Ollama + Gemini endpoints, `frame-src 'none'` and `object-src 'none'` block iframes and plugins. This is the primary defense against XSS — combined with the new in-memory-only key storage, the key-exfiltration path is closed. *(src-tauri/tauri.conf.json)*

### Vercel function abuse protection
All three Vercel serverless functions (`/api/translate/burst`, `/api/translate/full`, `/api/translate/tutor-explain`) now enforce:
- **Per-IP rate limiting**: 30 req/min, 200 req/hour. Returns 429 with `Retry-After` header on limit exceeded.
- **Input-size caps**: 10,000 chars max for `sourceText`, 5,000 for `targetPrefix`. Returns 413 on oversized input.

Previously, anyone could hit the endpoints indefinitely and either exhaust the env-default Gemini API key quota or rack up charges for whoever's key was used. *(api/_lib/rate-limit.ts, all 3 endpoints)*

## 🛡️ Reliability

### IndexedDB connection leak — fixed
`openDB()` was calling `indexedDB.open()` on every single CRUD operation, leaking a new `IDBDatabase` connection each time. Browsers cap concurrent IDB connections per origin (Chrome: ~75), so on a long-running session with frequent glossary mutations the pool would exhaust and **all DB operations would fail with `InvalidStateError`** — silent data loss. The connection is now cached and reused for the lifetime of the page, with auto-recovery if unexpectedly closed. *(src/lib/dual-storage.ts)*

### React Error Boundary — added
There was no React Error Boundary anywhere in the app — any uncaught render error would crash the entire React tree and show a blank screen. For a translation app where users may have unsaved drafts of long segments, that's a data-loss risk. A new `ErrorBoundary` component wraps the app at the top level AND each panel (Translator, Glossary, Models, API Keys, Settings, Dashboard) individually. A crash in one panel now shows a fallback UI with "Try again" / "Reload page" buttons instead of taking down the whole app. *(src/components/ErrorBoundary.tsx, src/App.tsx, src/components/WorkspaceShell.tsx)*

### Vercel warmup in Tauri — guarded
The 4-minute Vercel function warmup interval was running unconditionally, including in the Tauri desktop app — where there are no Vercel functions to keep warm. Every 4 minutes the Tauri app made a useless `fetch("/api/translate/burst")` that 404'd. Now guarded by `isTauriEnvironment()`. *(src/main.tsx)*

### useGemini retry logic — error-classified
The retry wrapper used to retry on ANY thrown error — including HTTP 4xx (invalid API key, malformed request). Retrying a 401 twice with backoff just delays the error and burns the user's API quota. Errors are now classified as `RetryableError` (network / 5xx / 429) or `FatalError` (4xx). Fatal errors are re-thrown immediately. *(src/lib/gemini-direct.ts, src/hooks/useGemini.ts)*

## 🗄️ Data Integrity

### Segment duplicates — fixed
The `segments` IndexedDB store used `autoIncrement: true` for its keyPath. Every call to `putToStore("segments", newEntry)` — where `newEntry` omitted `id` — created a **new row** instead of upserting. Re-confirming an edited segment added a duplicate; the DB grew unboundedly over a long translation session. The store is migrated to deterministic string ids (`"{sourceLang}-{targetLang}-{idx}"`), so re-confirming now upserts. DB schema bumped to v3 with a drop-and-recreate migration (acceptable because old data was full of duplicates anyway). *(src/lib/dual-storage.ts, src/components/editors/TranslationWorkspace.tsx)*

### Glossary ID collisions — fixed
Reference-DB glossary entries used hardcoded numeric ID ranges (10000+ for WIPO, 20000+ for Microsoft, 30000+ for OPUS). JSON-uploaded entries used `id: Date.now() + idx`. If a user uploaded a JSON file with >10000 entries, the IDs would overlap and `put()` (which upserts by key) would **silently overwrite** existing reference-DB entries. Reference-DB entries now use string ids (`"{dbId}-{idx}"`) which can't collide with auto-incremented numeric ids. JSON-uploaded entries no longer compute client-side ids at all — they let IndexedDB autoIncrement. *(src/components/GlossaryView.tsx, src/types.ts)*

## 🏗️ Architecture & Configuration

### Over-permissioned Tauri capabilities — tightened
The Tauri capability manifest granted `dialog:allow-open`, `dialog:allow-save`, `fs:allow-read-text-file`, `fs:allow-write-text-file` to the main window — but **neither the `fs` nor `dialog` plugin is actually used anywhere in the JS code**. File imports go through the browser's native `<input type="file">`. These were unused attack surface. Removed. *(src-tauri/capabilities/default.json)*

### Tauri updater signing — enabled (cheap fix, no paid certs)
The Tauri updater plugin was disabled in v0.2.0 because no signing keypair existed. A keypair has now been generated; the private key is stored as the `TAURI_SIGNING_PRIVATE_KEY` GitHub Actions secret and the public key is set in `tauri.conf.json → plugins.updater.pubkey`. The release workflow signs the bundles and uploads `latest.json` so the app can auto-update. **OS-level code signing** (Apple Developer ID for macOS Gatekeeper, Windows cert for SmartScreen) still requires paid certificates (~$99/yr Apple, ~$200/yr Windows) and is deferred — users will still see the "unverified developer" warning on first launch, but auto-updates now work. *(src-tauri/Cargo.toml, src-tauri/src/lib.rs, src-tauri/tauri.conf.json, .github/workflows/release.yml)*

### Vulnerable dependencies — updated
`npm audit fix` cleared the high-severity postcss path-traversal advisory (GHSA-r28c-9q8g-f849) and the moderate protobufjs DoS advisory (GHSA-j3f2-48v5-ccww). `npm audit` now reports **0 vulnerabilities**. *(package.json, package-lock.json)*

### cargo-audit in CI — added
The CI workflow now runs `cargo audit --deny warnings` against `src-tauri/Cargo.lock` on every push/PR. Any RUSTSEC advisory in a Rust transitive dependency will fail the build. *(src-tauri/Cargo.lock, .github/workflows/ci.yml)*

## 📥 Install

### Desktop (recommended)

Download the installer for your platform from the **Assets** section below. The installers will appear once the `Release` GitHub Actions workflow finishes building them.

- **Windows**: `RDAT Copilot_0.3.1_x64-setup.exe` (NSIS installer)
- **macOS Apple Silicon** (M1/M2/M3): `RDAT Copilot_0.3.1_aarch64.dmg`

After install, open the **Models** panel and click **Pull** on `gemma4:e2b` (~1.5 GB) to get the recommended starter model. See the [Getting Started guide](https://github.com/waleedmandour/rdat#getting-started) for full setup instructions.

### PWA (browser, no install)

Visit <https://rdat.vercel.app> (or your own Vercel deployment) in Chrome 113+ or Edge 113+ for browser-only mode with optional WebLLM inference.

## ⚠️ Known limitations (deferred to future releases)

1. **OS-level code signing** — Windows .exe and macOS .dmg are still unsigned (the cheap Tauri-updater fix doesn't cover this). Users will see SmartScreen / Gatekeeper warnings on first launch. Requires paid Apple Developer ID ($99/yr) + Windows code-signing cert ($200/yr).
2. **WelcomeWindow splash** is still intentionally always-dark (~30 `text-white/NN` opacity layers). Converting to theme-aware is mechanical but spread out.
3. **Reference-DB "Use" toggle** allows multiple DBs in use simultaneously. Exclusive single-DB use would be a small change if preferred.
4. **Comprehensive EN↔AR dictionary** — seed corpus is still ~85 hand-picked entries. Sourcing a licensed multi-thousand-entry bidirectional dictionary is still on the roadmap.
